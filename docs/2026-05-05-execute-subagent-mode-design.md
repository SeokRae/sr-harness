# execute 스킬 서브에이전트 모드 설계

**날짜**: 2026-05-05  
**대상 스킬**: `sr-harness:execute`  
**목표**: 복잡한 플랜 실행 시 서브에이전트 모드로 자동 전환, PR 충돌 없이 단일 feature PR로 완료

---

## 배경

현재 `execute` 스킬은 단일 에이전트가 순차적으로 모든 태스크를 처리한다.  
태스크 수가 많거나 파일/모듈이 분산된 경우 컨텍스트 오염과 집중력 저하가 발생한다.  
서브에이전트를 도입해 태스크별로 격리된 컨텍스트에서 구현하되, **PR은 하나**로 유지한다.

---

## 설계 결정

| 항목 | 결정 |
|------|------|
| 진입 방식 | `execute` 내부 자동 분기 (별도 스킬 없음) |
| 분기 기준 | 태스크 수 ≥ 3, 또는 태스크가 다른 파일/모듈에 분산 |
| 브랜치 전략 | 단일 feature 브랜치, 서브에이전트 순차 커밋 |
| PR 전략 | 기존 `submit` 스킬로 PR 1개 생성 |
| 충돌 방지 | 서브에이전트 병렬 dispatch 금지 + `git add .` 금지 |

---

## 섹션 1: 복잡도 판단 로직

`execute` 시작 시 플랜 파일(`.claude/session-plan.md`)을 읽어 실행 모드를 결정한다.

```
독립 태스크 수 ≥ 3           → 서브에이전트 모드
태스크가 다른 파일/모듈 분산  → 서브에이전트 모드 (수 무관)
그 외                        → 단일 실행 모드 (기존 그대로)
```

---

## 섹션 2: 서브에이전트 실행 모드

### 흐름

```
태스크 목록 추출 (플랜 파일에서 전문 추출)
      ↓
[태스크 N] 구현 서브에이전트 dispatch
  컨텍스트: 태스크 전문 + 관련 파일 경로 + 브랜치명 + worktree 경로
  서브에이전트: 구현 → 커밋 (git add {파일만} + commit -m "... (#이슈번호)")
      ↓
[태스크 N] 스펙 리뷰 서브에이전트 dispatch
  플랜 스펙 vs 구현 비교
  ❌ 불일치 → 구현 서브에이전트 재dispatch → 재리뷰
  ✅ 통과
      ↓
[태스크 N] 코드 품질 리뷰 서브에이전트 dispatch
  ❌ 이슈 → 구현 서브에이전트 재dispatch → 재리뷰
  ✅ 통과 → 다음 태스크
      ↓
모든 태스크 완료
      ↓
verify → submit (PR 1개, Closes #N)
```

### 충돌 방지 규칙 (서브에이전트에게 명시 전달)

- `git add .` 사용 금지 — 태스크 관련 파일만 명시적으로 지정
- 커밋 전 `git pull --rebase origin {브랜치명}` 실행 (선행 커밋 흡수)
- 구현 서브에이전트 병렬 dispatch 절대 금지 — 반드시 순차 실행
- 모든 커밋에 이슈 번호 포함: `feat: 설명 (#이슈번호)`

---

## 섹션 3: 기존 스킬 연동

서브에이전트 모드 완료 후 기존 워크플로우 그대로 이어진다.

```
execute (서브에이전트 모드) → verify → submit → finish
```

### `execute` 스킬 파일 구조 변경

```
## 전제 조건 (Worktree 확인)    ← 기존 유지
## 시작 전 체크포인트            ← 기존 유지
## 실행 모드 판단               ← 신규 추가
## 단일 실행 모드               ← 기존 내용 이동
## 서브에이전트 실행 모드        ← 신규 추가
## 완료 조건                    ← 기존 유지
## 예외 상황                    ← 기존 유지
```
