# 독립 analyze 프롬프트

analyze SKILL.md의 "실행 주체" 절이 새 에이전트에게 넘기는 고정 프롬프트입니다. 아래 `---` 뒤 전문을 그대로 넘기고 `{SKILL_DIR}`, `{REPO}`, `{N}` 세 자리만 채워요. 판정 기준과 보고 형식은 SKILL.md가 정본이라 여기에 옮겨 적지 않습니다.

| 자리 | 값 |
|------|-----|
| `{SKILL_DIR}` | analyze 스킬 폴더의 절대 경로 (이 파일의 상위 폴더) |
| `{REPO}` | feature 브랜치가 체크아웃된 저장소 루트의 절대 경로 |
| `{N}` | 이슈 번호 |

---

이 변경이 왜, 어떻게 만들어졌는지 모르는 상태에서 의도 정합성을 판정한다. 그 상태가 이 판정의 전제다.

1. `{SKILL_DIR}/SKILL.md`에서 `## 입력 수집`, `## 3가지 교차검증`, `## 결과 보고 형식` 세 절을 읽는다
2. 입력 수집의 명령을 `{REPO}`에서 이슈 번호 `{N}`으로 실행한다. 브랜치 이름에서 번호를 다시 뽑지 않는다
3. 세 가지를 교차검증하고, 마지막 메시지는 결과 보고 형식의 블록 하나로 낸다. ⚠️ 행의 근거 칸에는 해당 요구사항과 파일, 줄을 적는다

지킬 것:

- 근거는 Issue 본문과 diff뿐이다. `.claude/session-plan.md`, 커밋 메시지, PR 본문은 구현한 쪽의 설명이라 열지 않는다
- diff만으로 반영 여부를 정할 수 없으면 ✅로 올리지 않고, ⚠️ 행의 근거 칸에 그 사실을 적는다
- 파일을 고치거나 커밋하지 않고, 코드를 실행하지 않는다
- 다른 에이전트를 띄우지 않고, verify나 execute 같은 다음 단계를 부르지 않는다. 판정만 돌려준다
